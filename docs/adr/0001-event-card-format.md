# ADR-0001: 사건 카드를 출처 목록과 본문 블록으로

- 상태: 채택
- 날짜: 2026-10-26
- 관련: CLAUDE.md 4장, V4 마이그레이션(`V4__simplify_event.sql`)

## 배경

V3은 사건 하나를 주장 여러 개로 나누고, 주장마다 근거(출처, 장, 원문 인용)를 달았다(`event_claim`, `claim_evidence`). 신뢰도 등급(`confidence_tier`)도 화면에 배지로 보였다.

카드를 "2~3분 읽을거리"(본문 1,000~1,500자, 표, 사진)로 키우기로 하면서 문제가 생겼다.

- 문장마다 근거를 다는 구조는 긴 글을 쓰고 고치기 어렵고, 원문 인용을 따로 관리해야 한다.
- 원문 인용은 퍼블릭 도메인 자료만 실을 수 있어서, 한국 자료(군사편찬연구소 등)와 섞어 쓰면 형식이 갈린다.
- 신뢰도 배지와 "검수 전" 표시는 읽는 사람에게 도움이 되지 않는다고 판단했다.

## 결정

- 사실 확인은 원문으로 계속하되, 기록은 **사건 ↔ 출처(+장·쪽) 목록**(`event_source`)만 남긴다. 카드 맨 아래에 "기관, 제목, 장" 한 줄씩 적는다.
- `confidence_tier`를 없앤다. `status`(draft/reviewed)는 API 필터에만 쓴다.
- 본문은 블록 배열(`body` JSONB): 소제목, 문단, 표. 사진 블록은 이미지 라이선스 검사와 함께 따로 넣는다.
- 종류(`kind`) 6가지를 DB CHECK로 묶는다. 지도 마커 아이콘을 고른다.
- 블록 모양은 적재기가 JSON을 읽을 때 검사한다(`type`별 record, 표의 칸 수). DB는 jsonb 안을 보지 않는다.

## 검토한 대안

| 대안 | 장점 | 단점 |
| --- | --- | --- |
| 주장·근거 구조 유지 | 문장 단위로 근거를 추적할 수 있다 | 긴 글을 쓰고 고치기 어렵다. 인용 관리 부담 |
| 본문을 Markdown 글자로 | 쓰기 쉽다 | 표를 파싱할 라이브러리나 코드가 필요하다. 잘못 쓴 표를 적재 때 잡기 어렵다 |
| 블록마다 테이블(`event_section`, `event_table` …) | DB가 모든 모양을 검사한다 | 테이블과 조인이 늘어난다. 카드 한 장을 읽는 데 비해 무겁다 |

## 결과

- 사건 파일 하나가 카드 한 장과 그대로 대응해 쓰고 검수하기 쉽다.
- 어느 문장이 어느 쪽에 근거하는지는 데이터에 남지 않는다. 검수할 때 출처의 장·쪽을 보고 확인한다.
- 블록 종류를 늘리려면(사진, 그림) `EventJson.Block`, 적재기 검사, 프론트 `Block` 타입을 함께 고친다.
