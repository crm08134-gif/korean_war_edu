# ADR-0003: 소셜 로그인 + JWT 쿠키, 서버 세션 없음

- 상태: 채택
- 날짜: 2026-11-07 (2026-11-01~04 결정을 모아 적음)
- 관련: CLAUDE.md 7장, V11·V14

## 배경

게시판·인물 투표·AI 질문에 회원이 필요하다. 운영자가 한 명이라 개인정보와 비밀번호를 지키는 부담을 최소로 해야 한다.

## 결정

- 카카오·구글 소셜 로그인만. 제공자 회원 번호만 저장하고 이메일·프로필·비밀번호는 받지 않는다. 닉네임은 우리 화면에서.
- 서버 세션 없이(STATELESS) 액세스 토큰 JWT(15분)와 리프레시 토큰(32바이트 난수, 14일, DB에는 해시만)을 HttpOnly 쿠키로. 갱신마다 바꾸고(rotation), 재사용이 보이면 그 기기 묶음을 모두 끊는다.
- 쿠키 인증이라 CSRF 보호(`csrf.spa()`)를 켠다. 로그인 도중 state·nonce는 5분짜리 서명 쿠키.
- 카카오와 구글은 다른 계정이다. 이메일로 자동 병합하지 않는다.
- 탈퇴하면 회원 번호·닉네임을 지우고 행은 남긴다(글의 외래 키). 리프레시 토큰 행은 삭제.

## 검토한 대안

| 대안 | 장점 | 단점 |
| --- | --- | --- |
| 아이디·비밀번호 | 제공자에 묶이지 않는다 | 비밀번호 저장·재설정·유출 대응 부담 |
| 서버 세션 | 구현이 익숙하다 | 서버를 늘리면 세션 공유가 필요하다. 자바 직렬화 쿠키 위험 |
| 토큰을 localStorage에 | 프론트가 단순하다 | XSS 한 번에 토큰이 새 나간다 |

## 결과

- 개인정보 처리방침에 적을 정보가 적다.
- 제재·탈퇴 뒤 남은 액세스 토큰(최대 15분)은 쓰기 요청 때 DB의 회원 상태로 막아야 한다.
- 같은 사람이 두 계정으로 신고 2명을 채울 수 있다(ADR-0004).
