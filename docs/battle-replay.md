# 전투 재생 ("애니메이션 보기") 설계

전투 사건 카드의 "애니메이션 보기"를 누르면 지도가 전투 지역으로 확대되고, 며칠간의 전선과 부대 이동을 몇 초 동안 재생한다. 이 문서는 데모(2026-11-06, 사용자 확인)에서 정한 모양과, 전투를 하나씩 더할 때 매번 같은 방식으로 작업하기 위한 규칙이다. **전투를 더하거나 재생 화면을 고칠 때는 이 문서대로 한다.** 바꿀 일이 생기면 이 문서를 먼저 고친다.

## 1. 화면 (데모에서 확정)

- 버튼은 **`kind`가 `battle`이고 재생 데이터가 있는 사건 카드에만** 있다. 카드 머리말 아래 굵은 검정 버튼 "애니메이션 보기".
- 누르면 카드가 닫히고 지도가 전투 범위(`view`)로 확대된다. 머리말 카드는 "애니메이션 보기 · 대략적 재현"과 전투 이름, 닫기 버튼이다. 아래 패널 자리에는 재생 시트가 뜬다.
- **지도:** 앱의 지도 그대로다(북 빨강·남 파랑·바다·주변 나라). 전선은 날짜에 따라 움직이고, 양측 색도 전선을 따라 같이 바뀐다.
- **부대:** 흰 알약 모양 안에 국기와 부대 이름(예: `국군 11연대`)을 넣는다. 국기 테두리 2px은 진영색(유엔군 측 `#7da3ce`, 공산군 측 `#db8580`), 알약 테두리는 검정 1.5px. **연대급까지** 넣는다(사단·연대를 섞어 쓴다). 한 화면에 10개 안팎이 한계다.
- **공격·이동 화살표:** CMH 지도에 그려진 화살표를 굵은 화살표(선 5px, 흰 테두리, 삼각형 촉)로 그린다. 색은 유엔군 측 `#2f5f9e`, 공산군 측 `#a8403a`. 화살표는 **앞 날짜에서 그 날짜로 넘어가는 동안 꼬리에서 머리 쪽으로 자라나고**(구간의 85% 동안), 다음 구간이 시작되면 구간의 첫 30% 동안 흐려지며 사라진다. 그래서 날짜 버튼을 누르면 "그날까지 있었던 움직임"이 한 장으로 보인다. 화살촉 길이는 `view` 폭의 4%. 부대 알약은 지도 위(HTML)에 떠 있어 화살촉이 알약 밑에 들어가면 가려진다. 범례에 "공격·이동"을 단다(2026-11-06 사용자 결정, 부대가 지나온 점선 대신).
- **재생 시트:** 날짜(큰 글씨)와 "N / 전체", 그 날짜의 설명 한 줄, 날짜(키프레임) 버튼, 재생·일시 정지 버튼, 위치 막대, 맨 아래 회색 칸에 **"대략적 재현 · 근거 지도: …"**.
- **효과는 넣지 않는다.** 교전 표시, 폭발, 화면 흔들림은 데모에서 시험한 뒤 빼기로 했다(사용자 결정).
- 재생: 키프레임 사이를 같은 시간(2.5초)으로 나누고, 천천히 출발해 천천히 멈추게 보간한다. 날짜 간격에 비례시키지 않는다. 열면 바로 처음부터 재생한다.
- 닫기·Esc를 누르면 재생이 멈추고 보던 스냅샷과 카드로 돌아간다. 재생 중에는 ←/→로 스냅샷을 넘기지 않는다.
- 기기에서 "동작 줄이기"를 켠 사용자에게는 자동 재생 대신 첫 키프레임을 멈춘 채로 보인다(버튼으로 넘긴다).

## 2. 데이터: `data/battles/<사건 id>.json`

파일 이름은 사건 id(예: `dabudong.json`)이고, 사건 하나에 파일 하나다.

```json
{
  "eventId": "dabudong",
  "status": "draft",
  "view": { "west": 128.05, "south": 35.75, "east": 129.05, "north": 36.55 },
  "maps": [
    { "title": "CMH Pub 20-2(Appleman), Map 00 '지도 제목'", "note": "기준점 N개, loo_rms X km" }
  ],
  "units": [
    { "id": "rok-1-11", "name": "국군 11연대", "country": "kr", "side": "un" },
    { "id": "nk-13", "name": "북한 13사단", "country": "kp", "side": "communist" }
  ],
  "keyframes": [
    {
      "date": "1950-08-13",
      "caption": "그날 일어난 일 한 문장 (우리 말로 새로 쓴다)",
      "front": [[128.30, 36.40], [128.50, 36.20], [128.80, 36.35]],
      "positions": { "rok-1-11": [128.52, 36.10], "nk-13": [128.40, 36.30] }
    },
    {
      "date": "1950-08-18",
      "caption": "…",
      "front": null,
      "positions": { "rok-1-11": [128.50, 36.05], "nk-13": [128.45, 36.20] },
      "arrows": [
        { "side": "communist", "path": [[128.40, 36.30], [128.42, 36.24], [128.47, 36.18]] }
      ]
    }
  ]
}
```

| 칸 | 규칙 |
| --- | --- |
| `eventId` | 파일 이름과 같다. `kind`가 `battle`인 사건이어야 한다 |
| `status` | `draft`/`reviewed`. 사건과 같은 규칙(사용자가 "○○ 재생 reviewed"라고 말한 것만 바꾼다) |
| `view` | 재생할 때 지도에 맞출 범위(경위도). 모든 부대와 전선 조각이 안에 들어가야 한다 |
| `maps` | 근거 지도 1~4장. 화면 맨 아래에 그대로 보인다. `note`에는 읽은 방법과 오차를 적는다 |
| `units` | 10개 안팎(최대 12). `country`는 `frontend/public/flags/<country>.svg`, `side`는 `un`/`communist` |
| `keyframes` | 2~6개, 날짜 순서. 첫 날짜는 사건 시작일 이상, 마지막은 종료일 이하 |
| `caption` | 1~80자. 사건 카드와 같은 자료로 사실을 확인하고 우리 문장으로 쓴다 |
| `front` | 그날 전선 중 **전투 지역 조각만**, 서→동 경위도. 앱은 그날 이전의 가장 가까운 스냅샷 전선에서 조각 양 끝과 가장 가까운 두 점 사이를 이 조각으로 바꿔 끼운다. 조각이 없으면 스냅샷 전선 그대로 |
| `positions` | 그날 있는 부대만 적는다. 빠진 부대는 그날 안 보인다(앞뒤 날짜 사이에서 흐려지며 나타나고 사라진다) |
| `arrows` | **앞 날짜 다음 날부터 이 날짜까지**의 공격·이동 화살표, 날짜마다 8개까지. `side`는 `un`/`communist`, `path`는 꼬리 → 머리 순서의 경위도 2점 이상(휜 화살표는 가운데 점을 더 찍는다). 첫 날짜에는 달지 않는다. 없으면 빼거나 `null` |

**좌표는 지어내지 않는다.** 부대 위치, 전선 조각, 화살표는 `maps`에 적은 CMH 지도의 부대 표시(군대 부호)·전선·이동 화살표에서만 읽는다(3장). 지도에 화살표가 없는 날짜에는 화살표를 만들지 않는다. 지도에 없는 날짜는 키프레임으로 만들지 않는다.

## 3. 전투 하나를 더하는 순서

1. **전투 고르기:** `kind`가 `battle`인 사건 가운데 CMH 지도에 날짜별 부대 위치가 그려진 것. 처음 시험할 전투: 다부동, 장진호, 지평리.
2. **지도 받기:** CMH 공간사(Appleman, Mossman, Hermes)의 그 전투 지도를 고해상도로 받는다(퍼블릭 도메인). 클라우드에서는 CMH가 막혀 있어 사용자 PC의 내장 브라우저로 받는다. 원본 이미지는 저장소에 넣지 않는다.
3. **맞추기:** `scripts/frontline/frontline_tool.py`의 `sheet`로 픽셀 좌표를 읽고 `fit`으로 이미지 → 경위도 변환을 맞춘다. 판정 기준은 전선 스냅샷과 같다(`km_per_px` ≤ 0.5, `loo_rms_km` ≤ 1.5). 미달이면 사용자에게 알리고 결정을 받는다.
4. **읽기:** 지도에 그려진 날짜마다(`evening, 18 Aug` 같은 표기) 부대 표시의 가운데 픽셀과 전선을 읽어 `fit`으로 경위도로 바꾼다. 부대 표시가 넓은 타원이면 타원의 가운데를 쓴다. 지도 한 장에 날짜가 여럿이면 날짜마다 키프레임 하나. 이동 화살표는 꼬리 끝, 꺾이는 곳, 촉 끝을 차례로 찍어 `arrows`의 `path`로 넣고, 그 화살표가 가리키는 기간이 끝나는 날짜의 키프레임에 단다.
5. **글:** 키프레임마다 `caption`을 쓴다. 사실은 그 지도의 본문 장과 『6·25전쟁사』로 확인하고, 자료마다 다르면 다르다고 쓴다(1장 규칙).
6. **파일:** `data/battles/<사건 id>.json`을 `draft`로 넣는다. 백엔드 테스트가 형식을 검사한다.
7. **확인:** 백엔드를 `EVENTS_INCLUDE_DRAFTS=true`로 켜고 그 전투 카드 → "애니메이션 보기"에서 부대와 전선이 지도 그림과 맞는지 본다.
8. **PR:** `feat: 전투 재생 데이터 — <전투 이름>`. 본문에 근거 지도, 기준점 수와 오차, 읽은 날짜를 적는다.

## 4. 코드 구조

- **백엔드 `battle` 패키지**: `BattleCatalog`가 앱 시작 때 `classpath:battles/*.json`을 읽고 검사해 메모리에 둔다(참전국과 같은 방식, DB 없음). `GET /api/battles`(공개)는 재생 데이터 전부를 보낸다. 검수 전(draft)은 `EVENTS_INCLUDE_DRAFTS=true`일 때만.
  - 검사: 파일 이름과 `eventId`, 부대 id 중복, `side`·`country` 형식, 키프레임 수와 날짜 순서, `positions`의 부대가 `units`에 있는지, 좌표가 `view` 안인지, `caption` 길이, 화살표(개수, `side`, 점 2개 이상, `view` 안, 첫 날짜에는 없음). 사건의 종류·날짜는 `EventLoader`가 넣은 DB를 보고 한 번 더 검사한다.
- **프론트**
  - `lib/battles.ts`: 응답 타입, `fetchBattles`, 그날 전선 만들기(스냅샷 전선에 조각 끼우기 → 점 500개로 다시 찍기), 시각 `t`의 부대 위치·투명도와 자라는 화살표(`partialLine`) 계산.
  - `components/BattleReplay.tsx`: 재생 시트(날짜, 설명, 키프레임 버튼, 재생, 위치 막대, 근거 지도).
  - `FrontlineMap`은 `replay` 값을 받으면 스냅샷 대신 그 전선·부대·화살표(`map-style.ts`의 `arrowData`가 선과 촉을 만든다)를 그리고 `view`로 확대한다.
  - `WarMapApp`이 재생 상태(어느 전투, `t`, 재생 중인지)를 갖는다. `EventCard`는 재생 데이터가 있을 때만 버튼을 보인다.
